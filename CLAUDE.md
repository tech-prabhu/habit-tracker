## Project facts

- Expo SDK **57** (`expo ~57.0.x`), React Native 0.86, React 19.2, TypeScript strict. Versioned docs: https://docs.expo.dev/versions/v57.0.0/
- npm project (`package-lock.json`), so use `npx`, not `bunx`.
- `app.json` enables `experiments.reactCompiler` and `experiments.typedRoutes`. Route hrefs are type-checked; `.expo/types` is regenerated by `npx expo start`.
- Path aliases: `@/*` → `src/*`, `@/assets/*` → `assets/*`.
- No test runner is configured. Verify changes with `npx expo lint` and `npx tsc --noEmit`.
- `node scripts/generate-sounds.js` synthesizes the reward sounds into `assets/sounds/*.wav` (tick, chime, fanfare). Edit the script and rerun it instead of hand-editing the WAVs.

## Architecture

A local-only habit tracker. There is no backend: all state lives in a single reducer and is persisted to AsyncStorage.

**State (`src/lib/store.tsx` + `src/lib/model.ts`)**
- `AppState` (habits, entries, challenges, settings, onboarded) is one `useReducer` exposed through `StoreProvider`/`useStore()`. Every action goes through `reducer`, which runs the pure `evaluateChallenges` after each change. That is how challenges move to `completed`/`failed`.
- Progress is stored as an **append-only list of `Entry` records** (one per repetition, keyed by local `day` string `YYYY-MM-DD`), not as counters. Both `check` and `count` habits use entries, and "met" means `count >= habit.target`. Read counts through the memoized `CountIndex` (`store.index` / `store.count()`), not by scanning `entries`.
- Persistence: the whole state is written to the `habits:v2` key on every change. `habits:v1` is migrated by `migrateV1`. If you change the shape of `AppState`, keep loading old data working: `loadState` spreads over `INITIAL_STATE`, and a breaking change needs a new key plus a migration.
- An `AppState` 'active' listener dispatches `refresh` so that date-dependent logic (challenge failure, reminders) runs again after midnight.
- All date logic uses local-time day keys from `src/lib/dates.ts`. Don't use `toISOString()` (it is UTC).

**Reminders (`src/lib/notifications.ts`, `src/lib/notifications-api.ts`)**
- Reminders are rebuilt from state, not tracked one by one. After each state change (debounced 1.5s) the store calls `rescheduleReminders`, which cancels all scheduled notifications and reschedules the next 7 days from `planReminders` (a pure function). Keep the total under iOS's limit of 64 pending notifications.
- **Never `import ... from 'expo-notifications'` at runtime.** The package root throws on Android in Expo Go because it registers for remote push. `notificationsApi()` lazy-`require`s only the local-scheduling submodules from `expo-notifications/build/*` and returns `null` when they're unavailable (including on web). Type-only imports from the root are fine.

**Feedback (`src/lib/feedback.tsx`)**: `useFeedback().reward(level, point?)` is the single entry point for haptics, sounds (expo-audio) and confetti bursts. It respects `settings.sound` and `settings.haptics`.

**Routing (`src/app/`)**: the root `_layout.tsx` holds the splash screen until the store has loaded, then renders a Stack with `(tabs)`, `onboarding` and a modal `habit-form`. `(tabs)/_layout.tsx` redirects to `/onboarding` when `!state.onboarded`.

**Styling**: plain `StyleSheet` with colors from `useColors()` (`src/lib/theme.ts`, light and dark palettes). Shared primitives such as `Button` live in `src/components/ui.tsx`.
